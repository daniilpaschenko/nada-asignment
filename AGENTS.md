Инструкции для AI-агента.
Здесь: правила, стек, текст задания, согласованные решения, план работы и definition of done.

---

## 1. Правила работы (ВАЖНОЕ)

- **Стек обязателен:** riverpod_flutter + riverpod_annotation, clean architecture
  (feature-first), go_router, retrofit, get_it + injectable, build_runner.
- **Можно требовать/использовать:** freezed, json_serializable.
- **Новые технологии** (любые, помимо перечисленных) — сначала спросить одобрение у меня.
- **Язык:** все коммиты и комментарии к коду — строго на английском.
- **UI и все тексты приложения** — на английском + адаптивны (т.е. зависят от ширины экрана).
- **Тема приложения** – создать в папке core/themes/ три файла – app_theme.dart , app_colors.dart и app_dimens.dart, чтобы не было захардкоженного нигде ничего.

## 3. Задание

### 01. Загрузка предоставленных профилей

Используйте общий набор данных из 24 профилей:

```
https://gist.githubusercontent.com/jordandivyansh/c96fa18f141e0abb904e394eb91fbabb/raw/d235446f37cd51aad4cfffa2b76483498c27a7b9/take-home-profiles.json?
```

- Загружайте файл по HTTPS-ссылке **сетевым запросом**, не добавляйте локальную копию.
- Ссылка возвращает обычный текст; **самостоятельно декодируйте тело ответа как JSON**.
- Объект верхнего уровня содержит массив `profiles`.

### 02. Первый экран: список профилей

- Для каждого профиля — отдельная строка: **имя, возраст, город, `connected_through`**.
- В верхней части — поле поиска.
- Фильтрация по **имени и городу** по мере ввода, **регистронезависимая**.
- Состояния:
  - loading — во время получения файла;
  - empty — сообщение `No profiles match`;
  - error — сообщение + кнопка повтора при неудачном запросе.

### 03. Второй экран: подробности профиля

- Открывается по нажатию на строку.
- Показывать все присутствующие поля.
- **Выделить** строку `connected_through`.
- Есть возможность вернуться назад.
- Если связи пока нет — сообщить об этом прямо и понятно.
- Обрабатывать отсутствующие значения и `null` без сбоев и без запутанных заглушек.

### 04. Обработка предоставленных данных

В данных есть: отсутствующие/`null` поля, один профиль без связи, длинный текст,
один профиль с текстом на хинди. Все профили должны отображаться **без сбоев и без
выхода текста за границы экрана**.

### 05. Тестирование и документация

- **Тест виджета** (минимум один): например, ввод в поиск фильтрует список,
  или несовпадающий запрос показывает `No profiles match`. Провайдеры отдают фейковые данные.
- **README** должен описывать:
  1. запуск приложения в Android-эмуляторе / iOS-симуляторе;
  2. запуск теста виджета;
  3. что сделали бы дальше при наличии времени;
  4. какие AI-инструменты использовались.

## 4. План работы

### Этап 1. Зависимости и инфраструктура
1. Dependencies: `flutter_riverpod`, `riverpod_annotation`, `go_router`, `retrofit`,
   `dio`, `get_it`, `injectable`, `freezed_annotation`, `json_annotation`.
2. Dev dependencies: `build_runner`, `riverpod_generator`, `retrofit_generator`,
   `injectable_generator`, `json_serializable`, `freezed`, `riverpod_lint`.
3. Настроить `analysis_options.yaml` и `build.yaml` (пути генерации, отключение лишнего вывода).

### Этап 2. Core-слой
4. `core/network` — Dio + Retrofit-клиент, baseUrl, логирование.
5. `core/di` — `injectable`/`get_it`, `configureDependencies()`.
6. `core/router` — `go_router`, маршруты `/` и `/profile/:id`.
7. `core/error` — Failure/Exception и их маппинг.

### Этап 3. Feature `profiles` (data / domain / presentation)
8. **Domain:** сущность `Profile` (все поля nullable-safe), абстрактный репозиторий,
   use cases (например `GetProfiles`, `FilterProfiles`).
9. **Data:** DTO на `freezed` + `json_serializable`, Retrofit-сервис `GET` по ссылке
   (ответ — plain text, декодируем как JSON → `profiles[]`), реализация репозитория.
10. **Presentation:** `AsyncNotifier`/`Notifier` для загрузки и поиска; фильтрация
    по name + city регистронезависимо (`.toLowerCase()`).

### Этап 4. UI / экраны
11. **Список:** `TextField` поиска, `AsyncValue.when` → loading / error (с Retry) /
    empty (`No profiles match`) / список строк (имя, возраст, город, `connected_through`).
12. **Детали:** открытие по `id`, показ присутствующих полей, выделение
    `connected_through`, кнопка «назад», понятное сообщение при отсутствии связи.
13. **Защита от переполнения** (длинный текст, Hindi) — `Expanded`/`Flexible`,
    `softWrap`, `overflow`, `scroll`-обёртки.

### Этап 5. Тестирование
14. Widget test: ввод в поиск фильтрует список ИЛИ несовпадающий запрос →
    `No profiles match`, с провайдерами, отдающими фейковые данные.

### Этап 6. README и финал
15. README: запуск на Android-эмуляторе/iOS-симуляторе, запуск теста (`flutter test`),
    что сделал бы далее, какие AI-инструменты использовал.
16. Прогнать `flutter analyze` и `flutter test`, финальная проверка, коммиты на английском.
